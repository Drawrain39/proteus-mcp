# 架构

Codex 把自然语言整理为 CircuitSpec。校验器核对逻辑器件、属性、端点和网络，再由布局器为支持的 LED 串联拓扑生成相对网格和连线计划。逻辑脚名与 Proteus 库内脚名分开，执行阶段由当前器件的状态栏、属性或网表确认映射。

| 层 | 入口 | 职责 |
| --- | --- | --- |
| 规格 | `circuit_validate`、`schema` | 严格校验 JSON、数量值、网络连通和 LED 极性 |
| 计划 | `circuit_plan`、`dry-run` | 分配相对布局、列出每条网络端点与验收步骤 |
| 运行 | `circuit_run`、`run` | mock 路径记录步骤。Windows 路径检查窗口并分配目标路径 |
| 执行 | `proteus_observe`、`proteus_action`、`proteus_canvas_batch` | 单任务管理 Windows-MCP stdio 子进程，按最新窗口图像执行单步或批量画布输入 |
| 证据 | `circuit_record`、`proteus_release` | 汇集观察、原生工程和哈希，交回桌面控制 |

GUI 适配器使用物理桌面像素计算前台 Proteus 的可见矩形。位置参数以返回截图的宽高归一化，局部截图使用自己的矩形。输入前核对进程、窗口、矩形和点击命中的窗口。每次观察清除旧令牌，失败后保留日志并停止当前操作。输入或截图失败可能出现在实际动作发出之后，因此恢复靠重新观察。

批量画布操作使用一张局部截图作为起点。服务逐点检查窗口及命中位置，完成后回传一张局部截图。该工具需要调用者从图中确认点击点及操作顺序。窗口检查能发现焦点、对话框和窗口矩形变化，不能识别原理图内的平移或连线状态变化。

每次运行使用新目录，目标工程名来自验证通过的规格。原生工程由 Proteus 的保存命令生成。Windows-MCP 截图与 JSONL 位于同一运行目录，记录工具检查截图是否来自本次运行，并为工程计算 SHA-256。同名逻辑 SDF 导出存在时，服务比对实际器件和值、引脚和全部网络端点。仿真行为和日志由执行者核对并记录。

| 状态 | 含义 |
| --- | --- |
| `PASS` | 对应当前层通过，例如逻辑校验、握手或 mock |
| `READY` | 已检查真实运行前置条件并分配工程路径 |
| `RECORDED` | 已记录本次真实工程文件与代理提供的观察 |
| `BLOCKED` | 当前前置条件缺失，或规格是尚不可执行的 MCU 草案 |
| `FAIL` | 校验、传输或输入处理出现错误 |
| `UNVERIFIED` | 仿真或实际库引脚还需要验证 |

当前 Windows 流程由 MCP 客户端按截图编排。最小 LED 工程已在本机保存、关闭重开、仿真并导出网表。AT89C51 与 Keil 的编译和 HEX 加载在可选阶段。
